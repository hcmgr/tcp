retransmission capability for send-side
    - rto
    - triple-dup-ack
nagle
    - delay sending segments if still unack'd data in-flight, wait for an ack to send it
delayed ack
    - try buffer the acks

problem
    - nagle AND delayed ack both enabled interact badly
    - e.g.
        - peer delaying ack
        - you're nagle is waiting on that ack to send a segment

tcp options

        - MSS (syn only)
            - mandatory to respect
        - window scale (syn only)
            - enabled if both specify

rto
    purpose
        - connection-wide timer to trigger re-tx of oldest unack'd segment

    on rto timeout
        restart rto event
        send oldest unack'd

    on send_segment() (i.e. when we actually have an outgoing segment)
        if oldest unack'd segment
            start rto timer (it should not have been active, if so, error)

    on ack
        advance una
        if rto active
            restart rto for new oldest unack'd segment (if one exists)

triple-dup-ack
    purpose
        - fast re-transmit mechanism (i.e. faster than rto)

    on receive triple dup ack
        (3 duplicates should be == una - i.e. we would have advanced una if they weren't)
        send oldest segment

delayed ack
    purpose
        - delay sending ack for Xms to maybe (a) piggyback on segment, or (b) buffer with other acks

    on send_ack()
        if ack timer active
            cancel ack timer
            send current cumulative ack
        else
            start ack timer for X ms
    
    on send_segment() (i.e. when we actually have an outgoing segment)
        if ack timer active
            cancel ack timer
            (we're sending current acknum in our segment anyway)
    
    on ack timeout
        send current cumulative ack
        (implicitly should be no ready_bytes, otherwise they would've been sent 
            and timer cancelled already)

nagle
    - if ready < MSS AND unack'd bytes in flight -> wait for ack to arrive before sending

    
Fast retransmit full example
    [peer A sender, peer B receiver]
    [peer A seqnum=0, peer B acknum=0]

    peer A: send seqnum=0 (500), nxt -> 500, una -> 0
    peer B: [packet dropped, e.g. network failure]

    peer A: send seqnum=500 (500), nxt -> 1000, una -> 0
    peer B: acknum 0

    peer A: send seqnum=1000 (500), nxt -> 1500, una -> 0
    peer B: acknum 0

    peer A: 
        [from last ack, triple-dup-ack, detected, retransmit oldest unack'd segment]
        send seqnum=0 (500), nxt -> 1500, una -> 0
    
    peer B:
        [has received seqnum=500-999 and seqnum=1000-1499 out-of-order validly]
        [on receipt of seqnum=0-499, can now cumulatively ack it all]
        acknum 1500
    
    peer A: send seqnum=1500 (500), nxt -> 2000, una -> 1500
